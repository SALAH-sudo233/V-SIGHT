# Candidate-Pool IoU=0 Mitigation Snapshot

This package contains only the previously validated candidate-replacement
experiment. It is not an oracle, forced-retrieval, or rejected verifier
experiment.

The frozen policy is `state_preserving_binding_aware_v1`:

1. Retain Qwen2.5-VL's original T1/T2/T4 existence/rejection state.
2. Replace a T2/T4 box only when Qwen already emitted a box.
3. Use the exact-query `binding_aware` candidate for both positives and the
   four negative types.
4. Do not read labels, GT boxes, or evaluation metrics in the decision rule.

## Validated result

| Metric | Qwen baseline | State-preserving candidate replacement |
| --- | ---: | ---: |
| T2 positive mIoU | 0.4672 | 0.4875 |
| T2 positive IoU=0 | 24.2% | 22.0% |
| T4 positive mIoU | 0.4223 | 0.4916 |
| T4 positive IoU=0 | 23.8% | 21.6% |
| T2 FG@Neg | 34.5% | 34.5% |
| T4 Neg HR | 33.9% | 33.9% |

The unchanged hallucination metrics are intentional: this policy changes bbox
coordinates but not whether the baseline emits a box.

## Layout

- `code/`: original candidate generation, state-preserving construction,
  oracle helper, evaluator source, and candidate-pool unit test.
- `data/refcocog_500_dev.semantic_strict.json`: repaired 500-group development
  benchmark.
- `data/qwen2.5-vl-7b.canonical_records.jsonl`: 7,500 frozen Qwen records.
- `data/binding_aware_positive_candidates/`: eight original positive candidate
  shards generated by the binding-aware prompt.
- `data/roh_vcd_state_preserving_records.jsonl`: frozen 7,500-record output of
  the validated policy.
- `results/`: metrics, provenance, validation status, and reports.

## Fast verification

Run from this directory:

```bash
python3 code/verify_effective_snapshot.py
```

The script has no model, GPU, image, or third-party Python dependency. It
checks the two record hashes, confirms that all `pred_found` states are
unchanged, and recomputes the reported T2/T4 mIoU and positive IoU=0 values.

## Rebuild boundary

The construction script requires 500 positive and 2,000 negative raw
`binding_aware` candidate records. The positive shards are included. The
historical negative shards were generated on VLM2 and are referenced by
`results/provenance.json`, but are not present in this local workspace. The
frozen final records include every candidate replacement that was actually
applied, so the validated result remains fully auditable and independently
checkable.

COCO image files and model weights are intentionally not copied. They are only
needed to regenerate candidate outputs, not to audit this result snapshot.
